# Main-kernel recovery (#98)

Recovery recreates the main WASM instance and reconstructs every open document from a healthy runtime checkpoint matching its current committed history position. Checkpoints reuse the existing saved envelope unchanged, including cached BREP values for stored shapes; they are not repository saves. Capture refuses open transactions and pending derived work. Missing checkpoints for the current committed undo position cause an explicit failure directing the user to Reload. A crash during a post-commit asynchronous rebuild advances history before capture can complete, so recovery cannot preserve that edit; Reload reopens saved content. Older checkpoints are never substituted automatically.

Every native instance owns its receivers and native arguments. Retirement is permanent, independent of public crash-state reset. A private synchronous preparation context selects only the new instance, leaving the public crash state and module unchanged on exit. Candidate nodes bind to their original document and temporarily resolve against their candidate tree; they do not publish tree notifications or undo records. All documents must reconstruct and validate before publication. A failure discards candidates and retains every live document and checkpoint.

The user explicitly approved clearing undo/redo during successful recovery on 2026-09-30. Publication may therefore establish a new runtime undo boundary after all candidates succeed. Current committed unsaved edits, document IDs, feature IDs and stable topology references must survive. Interrupted uncommitted transactions are excluded. Failed preparations must preserve the previous history stacks. No saved field, version, migration, cloud payload, or native binding is changed.

`AppBuilder.useWasmOcc()` installs the coordinator and checkpoint observers. The crash banner offers Recover and Reload, explicitly explaining that successful recovery clears undo/redo. `KernelRecovery.current` reports actual availability, recovering/failed state, and an error; repeated requests share one recovery. A post-activation viewport failure reports an error while the replacement kernel stays healthy, with Reload available to refresh the view.

Recovery cancels queued program jobs without waiting for jobs queued behind its own FIFO slot, aborts analyses and parametric background rebuilds, and asks an interactive command to cancel. It waits at most five seconds for an active command or transaction to roll back. Saves must settle before preparation; save settling and replacement module creation each have a thirty-second bound. Per-document mutation ownership and the autosave hold are released on success and failure. A late module created after the deadline is retired instead of installed.

Preparation reconstructs stored shapes from BREP and synchronously rebuilds parametric features against the candidate graph and its fresh variable/settings metadata. Invalid shapes or failed features refuse recovery rather than silently substituting older content. Plugin document implementations that do not support reconstruction also refuse recovery. Open documents must remain the same set through preparation. All candidates adopt in one synchronous turn; an adoption failure restores the original graphs before module activation. Activation then establishes the approved undo boundary, preserves clean/dirty status and notifies views.

The append-only `recover_kernel` MCP tool is exposed when recovery is installed and uses the normal page mutation FIFO. Scene-backed refs retain their node IDs; repeatable subshape, curve and surface queries re-derive against reconstructed nodes. Standalone native geometry and creation-operation snapshot extras are invalidated, because they have no reproducible scene query. Completed program-job results remain historical metadata; a ref reported there can be invalid after recovery. Retired native handles remain unusable even if public crash state is later reset or the old module is restored to a global variable.

Checkpoints are runtime-only and disappear when the tab closes. They do not change repository versions, document envelopes or saved payloads. Recovery is available only with a healthy checkpoint for the current committed history position; a crash before that checkpoint is available must be handled by Reload. Native reconstruction runs synchronously in the candidate main instance; its preparation context cannot span an `await`. #97 worker cancellation and #92 asynchronous program jobs remain separate features. The original historical scan failure has not been reproduced.


Verification includes real native tests for two-document preparation/publication failure atomicity, stable fillet edge IDs, stored/component geometry, variable-driven edits and subsequent undo/redo, interrupted transactions, scene-backed MCP refs, and replacement-module deadlines. Run `node packages/wasm/test/browser/run-kernel-recovery-smoke.mjs` for the actual application startup and Recover-button flow under deployment CSP in Chromium and Firefox. That browser probe explicitly injects a retired fatal generation; it does not claim reproduction of a historical native crash.
