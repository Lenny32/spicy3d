# Cancelable corner-setback jobs

Dedicated tools append to the existing tool list: `start_corner_setback_job`, `get_corner_setback_job`, and `cancel_corner_setback_job`. Start accepts an actual body node ID, existing fillet feature ID, three positive finite lengths or length expressions in the persisted selected-edge order, optional expected persistent refs, and an optional queue-inclusive deadline. Arguments are cloned before entering the shared page mutation FIFO.

The manager binds the job to its caller and captured document. It rejects a document switch before execution. Once started, the executor continues using that captured document, even if UI focus changes. Optional expected refs reject stale edge re-picks. The executor delegates to the parametric runtime's shared cancelable corner edit API; it does not perform geometry or implement its own rollback.

Start/status/cancel bypass the queue only through the existing private builtin identity registry. Actual modeling is scheduled inside the same FIFO. The existing manager enforces four active jobs per caller, sixteen retained jobs per manager, ten-minute terminal retention, a 1 MiB argument/result budget, and a finite deadline (120 seconds by default, maximum 600 seconds). Corner worker fitting separately has a strict 90-second deadline with worker termination and no synchronous fallback.

Cancellation remains responsive while fitting. Session end and main-kernel recovery cancel both ordinary program and corner managers through the existing hooks. Queued cancelled jobs skip runtime creation; active jobs report cancelling until the apply API settles. A committed success wins a later cancellation race and clears the cancellation reason. Failed preparation cannot replace a document snapshot over subsequent user edits.

Safe document/selection metadata reads use the existing committed snapshot while the apply API is pending; the snapshot is released in `finally` on completion, cancellation, and failure. Published-tool tests verify responsive status/selection reads and visibility of later user metadata edits after the operation settles. A separate published-tool regression delegates the real edit API with a controlled preparation barrier, removes the host body, and verifies that confirmation fails without resurrecting it, changing the deletion's history position, or retaining transaction/mutation ownership.

The published MCP path is tested with controlled worker/apply barriers for FIFO, input cloning, captured body/document binding, selection guards, session/recovery cancellation, retention, and completion races. These barriers are separate from native-fitting evidence.

`cornerJobs.kernel.test.ts` exercises the actual published MCP server, shared corner edit API, HybridShapeFactory, KernelWorkerHost and WorkerKernel with the pinned native module. Starting from the approved v12 fixture's ordinary fillet, the job fits the unequal 2.49/2.50/2.51 mm corner through one strict `cornerSetbackReplica` request before confirmation. It produces a valid positive-volume body, releases mutation/transaction ownership, and proves exact feature JSON/history undo plus redo. The test passed in 123 seconds including redo recomputation. This native loopback verifies the real worker protocol and geometry; independent worker realms and termination during blocked native execution are covered by the separate corner browser smoke.

Final validation against the approved membership guard: 473 tests across all 34 non-kernel AI files plus the shared corner edit API tests pass, as do the isolated checkout TypeScript and scoped Biome checks. The native published-tool proof passes separately. A read-only independent agent review found no blocking FIFO, caller/document binding, snapshot cleanup, or cancellation ownership issue. No saved-format change is introduced by the job layer.
