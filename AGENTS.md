# Spicy3D coding guidelines

## Build & Test

```bash
npm run dev            # Rspack dev server → localhost:8080
npm run build          # Production build (Rspack + SWC)
npm run test           # All tests (Rstest + Happy-DOM); npm run testc = with coverage
npm run check          # Biome lint + auto-fix (run before commits)
npm run format         # Biome + clang-format across all files
npm run build:wasm     # C++ → WebAssembly (CMake + Emscripten); setup:wasm = one-time deps

npx rstest packages/core/test/result.test.ts   # single file
npx rstest -t "should handle error case"       # filter by name
```

## Monorepo Structure

Browser-based parametric 3D CAD: OCCT C++ kernel compiled to WebAssembly, rendered with Three.js. npm workspace under `packages/`:

```
web ──> builder ──> app ──> core
                  ──> i18n / three / wasm ──> core
                  ──> ui ──> core + element
                  ──> parametric ──> core
                  ──> cloud ──> core, ai        (lazy, via useCloud; ai: its SDK-free half)
```

- **`core`** — Everything abstract: shape interfaces, math, document model, reactive data (`Observable`, `Binding`, `PubSub`), `Result<T,E>`, undo, commands, serialization, plugins, services, UI abstractions
- **`parametric`** — Parametric feature-list bodies (Onshape-style) plus the 2D sketch module (`src/sketch/`, wrapping the PlaneGCS constraint solver via `planegcs.ts`). A body stores no shapes — only an ordered feature list replayed through `registerFeature` handlers, so any upstream edit re-evaluates the chain; the bulk of the module is stable identity for sub-shapes across rebuilds (kernel history → tracked ids → stored `EdgeRef`/`ProfileRef`) and the timeline rules for which shape a reference resolves against.
- **`wasm`** — Concrete `ShapeFactory` → OCCT via Emscripten; exports `initWasm()`
- **`three`** — Three.js viewport, camera controller, visuals, highlighter, gizmo, mesh export
- **`element`** — Custom reactive DOM elements (radio groups, expanders, data converters)
- **`ui`** — App chrome: main window, ribbon, property panels, project tree, dialogs, toast, status bar
- **`app`** — `Application`, body nodes (`bodys/`), command implementations, `CommandService`, `HotkeyService`
- **`builder`** — `AppBuilder` fluent chain (`.useIndexedDB().useWasmOcc().useParametric().useThree().useUI().build()`), default ribbon layout; `mergeRibbonProfiles` merges module contributions (`SketchRibbonProfiles` from `@spicy3d/parametric`, `ParametricRibbonProfiles`) into `DefaultRibbon`
- **`cloud`** — Client of the SpicySrv HTTP API: `openapi.json` (the server's spec, committed) → `src/api/schema.generated.ts` (`openapi-typescript`; `npm run cloud:api [-- <path-or-url>]` regenerates, `cloud:api:check` / `generatedApi.test.ts` fail when stale — never edit it by hand); `CloudClient` (`openapi-fetch`; `call()` → `Result<CloudReply, CloudError>`, `X-Spicy3D-Request: 1` on unsafe methods, `ifMatch()`, `newIdempotencyKey()`), problem codes → i18n in `problem.ts`, `discoverCloud()` in `config.ts` (dependency-free; anything but a Spicy3D config → dormant; `public/api/config` is the no-server placeholder) and the `apiVersion` range → reload banner (`showBanner`); `Account` (`src/account/`, `Cloud.current.account`): observable `status`/`user` (`GET /api/me`), sign-up/in/out and every account call, `account.call()` = authenticated request that on a 401 marks the session `expired`, opens the re-login dialog and retries once (pending saves use it), `addSignOutHandler` (stop sync / clear the cloud cache, `removeCachedDocuments` per the device setting `keepOfflineCopies`, always after deletion); account UI in `src/ui/` (own `Modal`, title-bar `AccountButton` via core `TitleBar.items`, settings with `AccountSettingsSections` for other modules), mounted by `startAccountUi` only when a server answers; email links (`/verify-email`, `/reset-password`, `/confirm-email-change` → `links.ts`, taken by the web entry before startup). Server timestamps (core `dateTime.ts`): `parseUtc` (strict ISO 8601 with `Z`/`±hh:mm`, else `NaN`), `formatDateTime`/`formatDate`/`formatTime`, `formatRelative` + `setRelativeTime`/`relativeTimeParts` (full time as `title`, refreshed by `watchRelativeTimes`), `groupByLocalDay` (history groups, calendar days in the local zone); locale = `DATE_LOCALE` (browser, not UI language); format at render time; `dateTimeGuard.test.ts` fails on `toLocale*String`/`new Date(x)`/`Date.parse`/`Intl.*Format` elsewhere in `packages/*/src` (explicit allowlist); device documents keep the absolute date; cloud documents (`src/documents/`, `startCloudDocuments`): `CloudDocumentRepository` (`app.repositories.cloud` while signed in; a version = manifest from core's pure `splitManifest` — BREP strings, mesh buffers, images → `{ "$blob": sha256 }`, numbers as exact binary — plus content-addressed blobs: `POST /api/blobs/check`, raw `PUT` of the missing ones only, then create or `POST …/versions` with `If-Match` and an `Idempotency-Key` reused across retries; 409 → `SaveConflict` → the MVP conflict dialog via `repositories.conflictHandler`), IndexedDB blob cache (`spicy3d-cloud-cache`, cleared on sign-out unless offline copies are kept), one editing tab per document (`EditLocks`: Web Locks + BroadcastChannel handover, others read-only), title-bar status (`DocumentStatusItem`); signing out closes open cloud documents (unsaved changes offered as a device copy / `.spicy` first). Moves between repositories go through core's `transferDocument` (copies get a new id; an id already in the target is never overwritten without asking; `documentRepositoryChanged` event). `.spicy` files of the server export (`spicy3d.cloudVersion`) open through `decodeDocumentFile`. Document saves are serialized per document (`IDocument.settled()`); user settings (`src/settings/`, `startCloudSettings`): `CloudUserSettings` attaches to core's `AutosaveSettings` while signed in (`GET/PUT /api/me/settings`, `If-Match`; ETag `"0"` = never saved → this device's value is uploaded, otherwise the server wins; re-read on sign-in / tab focus / `online` / account settings open) and the autosave section of `AccountSettingsSections`; version history (`src/history/`, CLOUD-09): "Version history" from the title-bar status (history button, location menu) docks `VersionHistoryPanel` in core's `SidePanels.items` (right of the viewport, one at a time, `CloudDocuments.openHistory`): `listVersions` pages (cursor) newest first, `historyGroups` = `groupByLocalDay` + consecutive unnamed autosaves folded ("N autosaves"), "Manual only" = what the server never prunes (`isKept`: not `auto`, or labeled/pinned; client-side, pages on until a row shows), retention note from `config.storage.autosaveRetention`; `VersionHistory` actions: preview = a *separate* document (fresh id, `app.loadDocument` → migrations) on a `VersionPreviewRepository` (read-only, every save refused as `readOnly`/`preview`, banner with Restore / Back to latest) so the open document is never touched, a newer `formatVersion` is refused before downloading; restore = `restoreVersion` (`kind: restore`, parent = head via `If-Match`, same manifest/blobs referenced, retried on top of a moved head), asking save-first/discard/cancel for unsaved changes, then reopening the head; label/pin = `PATCH /api/versions/{id}`; save as new document; download `.spicy`; compare through core's `compareDocuments` / `DocumentDiffers` (`IDocumentDiffer`, default the semantic `SemanticDiffer`); offline-first sync (`src/sync/`, CLOUD-10): `SyncEngine` (attached to the repository by `CloudDocuments`) makes every cloud save local first — snapshot manifest + blobs into the blob cache, a `SyncRecord` (`sync` store of `spicy3d-cloud-cache`, DB v2 with `blobMeta` for the LRU cap) with `baseVersion`, `pendingKind` (manual wins, several offline saves = one push), a persisted push `attempt` (key *and* every field SpicySrv hashes with it — clientId, deviceName, name, kind, label, parents — resent as is after reloads or from another tab; `idempotency_key_reused` → new key via the 409 path) and `unconfirmed` pushes per clientId (a lost answer that landed becomes the merge base); snapshot blobs are written with `putStrict` before the record (a full disk fails the save as `quota`), eviction skips entries used in the last minute — so `document.save` resolves `saved` offline and `document.version` is set by the engine, never from the save result; per-document passes (states `clean/dirty/pushing/offline/diverged/merging/conflict/error`, jittered backoff, quota and a declined re-login stop until the next save/sign-in); pulls from `EventsChannel` (`/ws/events`, SRV `docs/events.md`: own `clientId` ignored, reconnect → refetch heads, 2.5-heartbeat watchdog, `session.revoked` → `account.refresh()`) plus focus/`online`; a clean document fast-forwards in place (`replaceContent`, "Updated from <device>"), unsaved edits get the head merged in, a pending save merges (`mergeDocuments`, then `validateMerge` with the registered `IMergeEvaluator` — merge-introduced rebuild failures become a `conflict`, no evaluator = pushed unvalidated with a log line; clean → one undo step + `merge` version with parents `[head, own base]`), conflicts wait in `conflict` (autosave held meanwhile; a closed document lets its lock go) (`syncConflictOf`/`onChanged`/`resolve`/`hold` for CLOUD-13; the MVP dialog gets `ConflictSyncActions`); content is only replaced from a fresh task with no save in flight and the user idle (core `UserActivity`, shared with `AutosaveService`: "Remote changes pending" otherwise); only the edit-lock holder syncs (a closed document with pending changes keeps its lock until pushed; startup pushes earlier sessions' records); `load` prefers the pending snapshot, offline the last synced base, `list` offline = the records (`syncState` badges on the home page); offline startup = `discoverCloud({ offlineCache })` (last `/api/config`; kept on unreachable / 5xx / non-JSON, forgotten on 404 or an incompatible config) + the cached user (`CloudDeviceSettings.lastUser()`, max 30 days since the server last confirmed it, cleared on any 401; `Account.confirmSession()` runs before the sync sends anything); a restore flushes pending saves first; sign-out removing copies keeps closed documents' unsynced saves as device copies. Tests: `test/_helpers/syncHarness.ts` (`Device`, `SyncDoc`, `FlakyNetwork`, `FakeEventsServer`, seeded fault injection in `sync.test.ts`); conflict resolution (`src/conflicts/`, CLOUD-13): the Conflict pill, the conflict toast's Resolve and a save meeting a conflict open `ConflictPanel` (side panel, `CloudDocuments.openConflicts`; the MVP dialog only when there is no merge result) over `ConflictResolution`, which holds the sync + autosave (`SyncEngine.hold`; a newer head still re-merges in `conflict`), keeps choices by path and reapplies them with `reapplyResolutions` (rounds: a conflict a choice creates is answered too; paths gone are dropped with a note), previews the merge in a *separate* read-only document (`MergePreviewRepository`, debounced `replaceContent`) so the open document — this device's side — is never touched until Finish, which re-merges with the document as it is, rebuilds (`validateMerge`; rebuild failures need `accept` or a fix + Re-validate) and calls `SyncEngine.resolve`; rows reveal their object via core `revealMergePath` (selection, `requestFeatureFocus` for the timeline, `MergePathRevealers` — the sketch module selects entities); sides labelled with device + local time, "Agent (MCP)" for `mcp` versions; save as a copy / open latest / export merge report. A clean merge's toast (`showActionToast`, several actions) offers View changes (`compareDocuments` from the pre-merge state) and Undo merge (`SyncEngine.undoMerge`: pre-merge content back as one undo step, record back on its old base with this device's changes pending, then held in `conflict` with `undone` — never pushed on top of the merge, never merged again by itself; refused once edited after the merge; per session). Tests: `conflictPanel.test.ts`, every merge fixture through the panel in `packages/builder/test/mergeConflictPanel.test.ts`
- **`i18n`** / **`storage`** / **`web`** — Locale data (en) / IndexedDB persistence / entry point (loading screen, `?plugin=`/`?url=`/`?model=` params)
- **Deployment** (CLOUD-16, `docs/deployment.md`) — one build for every host, nothing server-specific baked in: the server is the page's origin (`/api/config`), per-deployment settings in `deployment.json` next to `index.html` (core `DeploymentConfig`, `AppBuilder.useDeploymentConfig()`; modules read their own section: `ai.presets`/`defaultPreset`/`hideBuiltInPresets` → `providerPresets()`); `warnIfInsecureContext` (builder) = banner over plain HTTP off loopback; `npm run check:urls` (allowlist in `scripts/check-external-urls.mjs`, sources + `dist/`) and `npm run smoke` (`scripts/smoke-offline.mjs`: the build in headless Chromium, other origins blocked, kernel + local save/open + banner, CSP read from `docker/default.conf.template`; `--url <deployment> --expect-server`); `SPICY3D_API_URL=<SpicySrv> npm run dev` proxies `/api/*`, `/ws/*` (not `/ws`, the dev server's live reload), `/mcp*` (server with `Spicy__PublicUrl=http://localhost:8080`); image `spicy3d-web` = `nginxinc/nginx-unprivileged` (digest-pinned), port 8080, read-only (Dockerfile: `docker build .` from source, `--target prebuilt --build-context dist=<folder>` packages a built `dist/` into the same hardened runtime; `deploy.yml` job `image` runs the tested `dist/` that way — read-only, headers, origin validation, `npm run smoke -- --url`, `docker load` artifact — then job `docker`, main/tags only, pushes `ghcr.io/<owner>/<repo>` `latest` + version for amd64/arm64; `compose.yml` pulls it), its own CSP from `docker/default.conf.template` rendered into `/tmp` (`'unsafe-eval'` for embind, `blob:` for plugins, extra plugin origins from `SPICY3D_PLUGIN_ORIGINS`, no `https:` in `connect-src` — LLM endpoints etc. from `SPICY3D_CONNECT_ORIGINS`, checked by `docker/19-spicy3d-plugin-origins.sh`); plugins bundle their dependencies (no CDN), and their import maps are applied by `app/src/pluginModules.ts` (`linkPluginModules`: mapped specifiers rewritten to blob: URLs, no inline `<script type="importmap">`; `scopes`/cycles fall back to inline)
- **Client security** (CLOUD-17, `docs/security.md`) — plugins (`?plugin=`, plugin manager) and `?url=`/`?model=` files go through core `ExternalContentPolicy` (`<app folder>/plugins/` for plugins, the app folder minus the server's `/api` `/ws` `/mcp` for files, or `deployment.json` `security.pluginOrigins`/`fileOrigins` load at once; a `.spicyplugin` link — by decoded path — always takes the plugin route; other http(s) origins ask, naming the origin; other schemes refused); while a cloud session may exist (`setSessionProbe`: `useCloud` says yes until discovery, `startCloud` = account not `signedOut`) saved plugin trust is ignored and a Trust lasts for the page only. Log URLs / foreign error text through core `redactUrl`/`redactSecrets`, document ids not names; a new raw `fetch`/WebSocket must be added to `packages/cloud/test/requestSurface.test.ts` (CSRF review); new storage keys go into the sign-out table of `docs/security.md`; sign-out also forgets MCP pairing decisions and closes an agent's open-document question (CLOUD-15 cloud tools, prompt text marks document names/labels as data). MCP SDK, `openapi-fetch`, `openapi-typescript` are pinned exactly (`dependencyPins.test.ts`); CI runs `npm audit --audit-level=high` on all deps.

Import via workspace names (`import { ... } from "@spicy3d/core"`); one root `tsconfig.json` covers all packages.

## C++ WASM (`cpp/`)

OCCT v8.0.0 → `spicy-wasm.wasm` via Emscripten. `cpp/src/`: `factory.cpp` (shape creation; the tracked ops report per-output history twice — single-valued `faceMap`/`edgeMap` keeping the first ancestor, plus flat (out, in) `faceAncestors`/`edgeAncestors` pairs keeping every derivation so boolean-merged faces record all their inputs), `shape.cpp` (topology traversal), `converter.cpp` (STEP/IGES/BREP/STL), `mesher.cpp` (B-rep → mesh), `geometry.cpp` (curve/surface queries). The Release build sets `-sDISABLE_EXCEPTION_CATCHING=1`, so any OCCT raise aborts the whole module and C++ try/catch is ineffective — the query files (`shape.cpp`/`mesher.cpp`/`geometry.cpp`) guard degenerate and null-geometry paths preventively (`IsGeometric`/`IsNull`/`IsDone` prechecks; `Edge::curve` reports degenerate edges through a JS-level throw, which still works with catching disabled), and the tracked sweep ops report cap faces through a separate `capFaces` channel on the tracked result (`LastShape()` of the sweep; empty when it coincides with `FirstShape()`, e.g. a 360° revolve). Output: `packages/wasm/lib/spicy-wasm.{wasm,js,d.ts}`. C++ style: WebKit (clang-format); license LGPL-3.0 (TS is AGPL-3.0).

## Key Patterns

- **Interface-driven** — `core` defines interfaces; feature packages implement; `AppBuilder` wires at startup.
- **Result pattern** — Fallible ops return `Result.ok(value)` / `Result.err(error)` (`core/src/foundation/result.ts`); never throw for expected failures.
- **Reactive data** — `Observable` uses `getPrivateValue(key)` / `setPrivateValue(key, value)`; setting emits `emitPropertyChanged`. `ObservableCollection` powers property editor and project tree.
- **Serialization** — `@serializable()` on classes, `@serialize()` on fields → `{ __cla$$__: "ClassName", ...props }`.
- **Merge** — three-way merge of two versions against their base (CLOUD-11 spec: `docs/merge.md`; engine CLOUD-12): declarations in `core/src/merge/` (`MergeConflict`/`Change`, id-only `mergePath`, `MergeRules` registry). **Every `@serializable` class needs a merge rule** (`registerMergeRule` next to the class's module; `packages/builder/test/mergeRules.test.ts` fails otherwise, `npm run merge:rules` regenerates the list in the spec); a changed payload shape updates its payload rule. Fixtures: `packages/core/test/fixtures/merge/` (`npm run merge:fixtures`, `loadMergeFixtures()`). Ids must be globally unique across devices — sketch entity/constraint/external ids are random (`parametric/src/sketch/sketchIds.ts`), never `max + 1` (UI labels number sketch items by their place, never by id). Engine (pure, sync, over `Serialized` — assembled or manifests, values compared with `$blob` refs by a sync SHA-256): `mergeDocuments` → `Result<MergeResult>` (`merged`, ordered `conflicts`, `changes`, migrated `inputs`), `resolveMerge`/`applyResolutions` re-merge with choices by path, `diffDocuments` (two-way, same paths); `validateMerge` (async, progress + `AbortSignal`) adds `rebuild-failure` via an `IMergeEvaluator` (the app's `HeadlessDocumentEvaluator`: `Document.loadHeadless`, `NullVisual`); `applyMergeToDocument` → `IDocument.replaceContent` (in place, one undo step, `ModelManager.applyContent` keeps unchanged nodes, one batched notification — also CLOUD-10's pull). Compare = `DocumentDiffers` (default `SemanticDiffer`, `summarizeChanges`). Merge tests needing every rule live in `packages/builder/test/merge*.test.ts` (fast-check property tests there), kernel validation in `parametric/test/mergeValidation.kernel.test.ts`.
- **Document format** — the saved envelope carries `formatVersion` (`DOCUMENT_FORMAT_VERSION`, `core/src/documentFormat.ts`) and `moduleVersions` (`parametric`/`sketch`, registered in `parametric/src/migrations.ts`); `Document.load` runs `DocumentMigrations.migrate` first (newer / non-Spicy3D files → toast, data untouched), and nodes of unregistered classes load as `UnknownNode`, saved back verbatim. **Changing the shape of any `@serialize()` field or stored payload requires bumping the owning version, a `registerMigration(module, from, migrate)` step (pure `Serialized → Serialized`, no DOM/WASM, never touching `userData`) and a new fixture in `packages/core/test/fixtures/documents/v<N>/`; existing fixtures are never edited.**
- **Document persistence** — through `IDocumentRepository` (`core/src/foundation/documentRepository.ts`: `list`/`load`/`save`/`delete`, all `Result`, a stale cloud save is a `conflict` outcome); `app.repositories.local` (`LocalDocumentRepository`, the only code touching the IndexedDB `documents`/`recents` tables) always, `.cloud` when signed in. Each document keeps its `repository` (+ `version`), `document.save(kind)` goes through it and `isDirty` compares `history.position()` with the saved one. `.spicy` files = gzipped JSON (`core/src/documentFile.ts`; plain-JSON `.cd` still opens), opened/saved by `app/src/documentFiles.ts` (File System Access API write-back where supported, download otherwise). **Autosave** — `AutosaveService` (app, an `IService`): per open document, `AutosaveSettings.intervalMinutes` (core; 0 = off, default 5; `localStorage` `spicy3d.settings.autosave` signed out, the account's value while signed in, cached for offline starts) after it became dirty, `document.save("auto")` — never while busy (`executingCommand`, pointer pressed, an open `<dialog>`, `AutosaveHolds.hold()` e.g. the sketch session — core `UserActivity`, also used by the cloud sync), then right after; a `.spicy` file with a handle is written back only with its per-file opt-in (`fileAutosave`), skipped otherwise; read-only (`repository.isReadOnly`) skipped; a conflict waits for the version to change (no dialog). UI state via core `AutosaveStatus` (status bar `AutosaveIndicator`, title-bar pill "Autosaved 14:05").
- **Body nodes** — `app/src/bodys/`; extend `ParameterShapeNode`, implement `generateShape(): Result<IShape>`, `setPropertyEmitShapeChanged()` triggers re-evaluation.
- **Commands** — `ICommand.execute(application): Promise<void>`; `CancelableCommand` adds `cancel()`, `AsyncController`, dispose stack.
- **Undo/redo** — `Transaction` records snapshots, `History` keeps the stack; commands create transactions automatically.
- **Plugins** — Loaded from URLs or `?plugin=`; manager in `core/src/plugin/` + `app/src/pluginManager.ts`; examples in `plugins/`.
- **Global singleton** — `getCurrentApplication()` (from `core`) instead of DI threading.
- **MCP server** — runs *in the browser page* (`packages/ai/src/mcp/`): an SDK `Server` over the same `buildTools()` registry as the old chat panel, reachable only through SpicySrv's relay (there is no local bridge any more). Tool calls are serialized (one `SerialQueue` for the page, reconnects included) because `run_program` refs chain across calls. **Remote MCP** (CLOUD-14): signed in to a server with `features.mcp`, cloud's `startCloudMcp` hands ai the `RemoteMcpLink` (`setRemoteMcpLink`, SDK-free `remote.ts`/`remoteState.ts`; signed out it hands `setRemoteMcpSignIn` the sign-in dialog instead), and the lazy `RemoteMcpSession` (over the generic reconnecting `McpSession`) connects to `config.mcp.pageSocket` (SRV-09 page protocol: `pageTransport.ts` = plain WebSocket, no subprotocol + `RelayTransport` for `notifications/spicy3d/*`; tab info on connect/document switch/focus — visible to any token of the user before Allow; a 1008 close re-checks the web session (`link.checkSession`) and reconnects with backoff unless signed out); the first non-listing request of each relay session waits for the pairing prompt (`PairingGate`: one prompt at a time, the token name shown as the trusted part, Deny = error `-32005` + 60 s cooldown for that token, "Deny all from this token"; decisions in sessionStorage bound to a tab instance id that a duplicated tab re-claims over BroadcastChannel; a request naming no session is refused; a request held by the prompt is dropped when its socket closes, and closing/reconnecting aborts every prompt), bound sessions show in the title-bar `AgentBadge` (Disconnect agent). The ribbon's MCP button / status-bar dot open `McpPanel` (`panel.ts`, SDK-free like `settings.ts`/`state.ts`/`remote.ts`; the SDK half `mcp/index.ts` is loaded with a dynamic `import()` once a link is there and the switch `mcp.settings` `remoteEnabled` is on): signed in = status, the switch, bound agents, recent calls, "Create access token…" and the Claude Code HTTP / JSON configs (`remoteClientConfigs`, also shown filled in after creating an MCP token); signed out = Sign in; no server with MCP = an explanation (`remoteStatusKey`). `capture_screenshot` takes `format`/`maxSize`/`quality` (default PNG, longest side `DEFAULT_MAX_SIZE` 1568: core `IView.snapshot(maxSize)` copies the fresh frame, scaled down, into an opaque 2D canvas, encoded with `toBlob` + `FileReader` — never a synchronous `toDataURL` of the full viewport, which froze the tab); relay calls (`imageByteBudget` server option → `withImageByteBudget`) re-encode it to fit the relay's `maxMessageBytes`, and a screenshot that cannot fit is an error result, never sent (`imageEncoding.ts`). **Cloud tools** (CLOUD-15, `tools/cloudTools.ts`): `spicy3d_open_document {id, version?}` / `spicy3d_new_document {name}` / `spicy3d_save {label?}`, MCP only, listed only while cloud's `CloudDocuments` lends `IAgentCloudLink` (`setAgentCloudLink`, SDK-free `cloudLink.ts`; `CloudAgentDocuments` in `cloud/src/mcp/`) — signed in — with `tools/list_changed` when it comes or goes; listing and history are the server's own `spicy3d_list_documents`/`spicy3d_document_history`; names must never be one SpicySrv answers itself (`spicy3d_connect/list_tabs/select_tab/list_documents/document_history`). Open over unsaved changes asks (`openConsent.ts`: Save and open / Open, keep unsaved / Cancel; one question per page, owned by the asking session — handlers get `ToolCallContext.caller`: the relay's agent id — and closed when that session ends (connection closed, agent gone from the relay's list) or on sign-out; a call waits `OPEN_WAIT_MS` 45 s, then answers `waitingForUser` and the retry waits for the same question; the other document stays open in its view tab; opening a `version` never asks); `version` = the history panel's read-only preview (`openHistoryOf`); new documents always go to the cloud; save = `document.save("mcp", { label })` + `sync.flush`; kinds and labels of saves sharing one write follow core's `combineSaves` (merge stays, manual wins, else the latest save's kind; a label only with its own kind — an agent's label never lands on the user's manual save or on an autosave holding the user's later edits), and the result reports the kind actually stored; a conflict opens `repositories.conflictHandler` once per document (not while it waits in `conflict` or its UI is showing) and the agent gets "Conflict pending user resolution" (agents never resolve). The server's sign-in listener is registered only once connected and removed with the connection. `spicy3d://document` adds `document` (id, location, headVersion, dirty, syncState, readOnly, preview); `MCP_SKILLS` = skills + `cloud-documents`; tokens made from the panel get `mcp:read`+`mcp:write` only; `documents:read` (needed by the server's list/history tools, but it also lets the token download every document over the REST API) is the dialog's explicit opt-in "Let agents list documents and history". Units: millimetres; angles: degrees.

## Testing

- Rstest (not Jest/Vitest) + Happy-DOM; root `rstest.config.ts`, globals enabled (`describe`, `test`, `expect`); tests in `packages/*/test/`; legacy decorators enabled.
- Reuse shared mocks from `@spicy3d/core/test-utils` (`TestDocument`, `createMockDocument`, `createMockApplication`, `createMockVisual`, ...) instead of per-package copies; package-specific facades (e.g. `packages/ui/test/_helpers/`) extend them. `initializeI18n()` runs automatically via rstest `setupFiles` — never call it in test files.
- Assertions must execute: none hidden in event callbacks (unless the callback is also asserted to fire), no tautologies (`x === true || x === false`), no `if (x) expect(...)` — assert the precondition, then the behavior; `await` every promise whose `.then` asserts.
- Assert behavior, not absence of crashes: bare `not.toThrow()` / `toBeDefined()` is a smell; `querySelector` results need `not.toBeNull()`.
- Restore global monkeypatches (`PubSub.default.pub`, `globalThis.fetch`, ...) in `finally`/`afterEach`, or use `rs.stubGlobal` + `rs.unstubAllGlobals()`.
- Type `rs.fn` mocks with the real signature (`rs.fn((_edges: IEdge[]) => ...)`) so `mock.calls` typechecks; use `test.each` for near-identical repeated cases.

## Code Style

- Biome: 4-space indent, 110-col width, double quotes, semicolons always
- `I`-prefixed behavioral interfaces — plain data-carrier shapes stay unprefixed (`...Data`, `...Ref`, `...Options`, e.g. `SketchData`, `EdgeRef`); `camelCase` functions/variables/files; `PascalCase` classes; `UPPER_SNAKE_CASE` constants
- CSS Modules (`*.module.css`); type-only imports (`import type { IFoo }`)
- Every TS file starts with the AGPL-3.0 header:

```ts
// Part of the Spicy3D Project, derived from Chili3D, under the AGPL-3.0 License.
// See LICENSE file in the project root for full license information.
```

## Git

Commits: `<emoji> <type>(<scope>): <description>` — ✨ `feat` · 🐛 `fix` · ♻️ `refactor` · ✅ `test` · 📝 `docs` · 💄 `style` · 🔧 `chore`. Scope = package name. Active branch: `dev` → PR to `develop`.
